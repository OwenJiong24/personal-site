## 结论：公布的数字是时间戳，不是事实

**2026-11-04 到 11-12 这八天，五个费率页对同一个普通抓取器换了答案：一家变得可读，一家变得不可读，还有一个计划价掉了十美元。** 值得带走的不是那些数字，而是「我们在某天读到过」这件事必须永久地长在数字的写法里，否则文字会悄悄变成一句关于今天的主张。

## 带日期的读数

| 页面 | 2026-11-04 | 2026-11-10 | 2026-11-12 |
|---|---|---|---|
| eBay 卖家费率 | 重定向到错误页 | **200、337,368 字节，数字可解析** | 200、337,657 字节，可解析 |
| Etsy legal/fees | server error | 403 Forbidden | 403 Forbidden |
| Etsy 帮助中心费率文 | 404 | 404 | 404 |
| Etsy /sell | server error | 403 Forbidden | 403 Forbidden |
| Bonanza /fees | 404 | 404 | 404 |
| 我们自己的招商页 | 200，费率文字在 HTML 里 | 未测 | **200 但没有费率文字**：15,839 字节的 JS 外壳 |
| Shopify 定价 | Basic 29 / Grow 89 / Advanced 359 | 未测 | Basic **29** / Grow **79** / Advanced **299** |

其中两条值得多看一眼。Etsy 从「server error」变成「403」，是同一个判定换了张脸——页面照样拒绝抓取器，所以我们照样不写它的数字。**难受的是我们自己的那一条**：2026-11-04 还给过我们带日期读数的同一个 URL，现在返回外壳；`/seller`、`/become-seller`、`/fees`、`/pricing` 返回的是一模一样的 15,839 字节——那是单页应用的兜底，不是页面。**我们再也无法用"验证别人"的同一把尺子验证自己的费率文字。**

## 我对每个变化做了什么

一条都没删。2026-11-04 的数字留在它被发表的那一页上，带着自己的日期，因为源变了就把旧读数删掉，和把旧读数当成今天的数字一样是错的。变的是标签：旧读数现在标为**今天无法复核**，新读数带着自己的日期排在旁边。

Shopify 这一动，忽略它是要花钱的：2026-11-04 那篇指南用的是 Grow 89、Advanced 359。这两个数字在今天的定价页上是错的，照它做预算的读者每月会多算 10 美元和 60 美元。P1 在 2026-11-04 写成「到 11-11 至少有一个数字会动」，现在记为**命中**——它命中的原因跟我们的聪明无关：厂商一直在改价，而对一个数字保持诚实的唯一办法就是给它写日期。

## 这一段是关于我们，不是关于他们

一个写着「只印我们自己读到的数字」的站，必须能扛住它自己的页面没通过这个测试。2026-11-12，它就发生在自己身上。修法不是不再发布自己的费率文字，而是**把读取方法连同它的失败一起写出来**——这一页就是。**任何写着"读于某日"却再也读不回来的页面，都应该把这件事说明白。**

## 立场与核对日

- **P1（已判）**：2026-11-11 复取时至少一个数字会动 → **命中**，落在 2026-11-12（Shopify 的 Grow 与 Advanced）。
- **P2**：到 **2026-12-12**，我们的招商页要么重新在服务端渲染的 HTML 里公布费率文字，要么本站不再把自己的费率页当作可核验来源引用。二选一，公开写出来。
- **P3**：Etsy 的费率页到 **2027-01-15** 仍然会拒绝普通抓取器。如果他们开放了，"只写读到的数字"这条规则会变容易，我们会说出来。
