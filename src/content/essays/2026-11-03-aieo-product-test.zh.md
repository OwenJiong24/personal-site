## 一句话结论

**小站在 AIEO 上最便宜的第一步不是写"给 AI 看"的文章，而是让机器不跑 JS 也能把你的商品与事实读出来。**
我们把自己的一个商品页当试验田：同一个商品，在自家 listing 上对不执行 JS 的抓取器是一个空壳；
在个人站上它是静态 HTML，带 `Product` 结构化数据、FAQ、带日期的断言和一份 Markdown 镜像。
这篇是测试设计 + 基线数据，结果到点追加公布。

## 起点：2026-11-03 的一手实测（包含难堪的部分）

被测试的商品：大豆蜡烛制作套装（容器蜡烛，家用全套）。我们在浏览器与抓取器各读一次自家 listing，记下的事实是：

| 我们看到什么 | 数值 / 事实（2026-11-03） |
|---|---|
| 售价 / 划线价 | $54.99 / $89.99 |
| 库存文案 | 现货 287 件 |
| 评价数 | 0 条 |
| 分类路径 | Craft Supplies & Tools › Raw Materials |
| 页面结构化数据 | 只有 `Organization`（ZART 平台级），**没有 `Product`** |
| 不执行 JS 的抓取结果 | 只拿到标题与一句 cookie 同意文案，**商品正文、价格、内容物全部为空** |
| 渲染后的内容物 | 18 项：2.5 磅大豆蜡、10 支香精、10 支染料、14 根棉芯 + 6 根木芯 + 20 张烛芯贴、10 个容器、熔蜡杯、量杯、温度计、搅拌勺、20 个固芯器、耐热垫、10 只防烫指套、镊子、晶石与干花 |

三条解释：

1. 单页应用（SPA）在浏览器里没问题，**对不执行 JS 的抓取器等于空白页**。AI 引擎与不少搜索索引器属于后者。
2. 商品页没有 `Product` 结构化数据，等于放弃了搜索引擎与购物类答案引擎唯一能确定读到的字段（价格、库存、品牌、类目）。
3. 0 评价就写 0 评价。我们不在新页面伪造 `aggregateRating`，因为评分是买出来的，不是写出来的。

## 我们改出了什么（全部可核对）

- 产品页（英文根、中文 `/zh/`）：[orangeknows.com/products/soy-candle-kit](/products/soy-candle-kit)、
  [中文页](/zh/products/soy-candle-kit)。纯静态 HTML，不跑 JS 也能读全。
- 结构化数据：`Product` + `Offer`（价格、币种、库存状态、卖家、价格观察期）+ `FAQPage`（6 问）+ `BreadcrumbList`。
  不含评分字段。
- Markdown 镜像（给 AI 与脚本直接读）：`/m/products/soy-candle-kit.md`；
  整站索引 `/m/index.md`、全文语料 `/m/all.md`、`/llms.txt` 逐条附镜像地址。
- 响应头：`/m/*` 明确 `Content-Type: text/markdown`；`robots.txt` 逐条放行 19 个 AI 抓取器。
- 节日适配表用公开日历核对：感恩节 2026-11-26、黑五 11-27、小商家周六 11-28、网络星期一 11-30、
  光明节 2026-12-04 日落后起点烛至 12-12、圣诞节 12-25、宽扎节 12-26 起。
  **我们不在页面写发货截止承诺**：时效条款在 listing，我们不编交付时间。
- 记录链：本文进入 SHA-256 链（正文全文参与哈希，页脚链头可核对，第三方能从公开仓库重算）；
  商品页不进链——链是用来记"我们说过什么"，商品价格库存天天变，进链就是把波动冻进记录。
- 披露：第一方商品（我们自己的平台），不是联盟返佣链接；每页写明。

## 测什么：三层，各自能落地

| 层 | 问题 | 怎么测 | 谁负责 |
|---|---|---|---|
| 可取 | 不跑 JS 能不能拿到商品数据 | 用不执行 JS 的抓取器读产品页与 Markdown 镜像，记录字节数与字段数 | 现在就能测，已完成 |
| 可索引 | 页面进没进索引 | `site:` 查询（Google / Bing）+ Common Crawl 索引 API + `robots`/sitemap 自查 | 2026-11-10 |
| 可引用 | 提问时 AI 是否用我们 | 固定提问面板 × 引擎清单，逐次打分并留截图 | 2026-11-27、12-02、2027-01-15 |

### 打分口径（只允许三个状态，避免"感觉被引用了"）

## 可反驳的预测（写在这里，到期公布，不管结果是什么）

- **P1｜2026-11-10 前**：`site:orangeknows.com/products/soy-candle-kit` 在 Google 或 Bing 至少一边命中。
  没命中就是负结果，我们会写清用了哪些提交手段。
- **P2｜2026-11-26 至 12-25 窗口内**：10 条提问面板里，至少 1 条在至少 1 个引擎得到 `cited`。
  基线是 2026-11-02 的同一套提问法：引用数为 0（那篇预测的核对日是 2026-12-02，见文末链接）。
- **P3｜现在已成立**：不跑 JS 的抓取器从我们的页面能拿到完整商品字段，从自家 listing 拿不到。
  这条已经在 2026-11-03 实测成立，是这轮最硬的一条结论。
- **P4｜2027-01-15**：给出节日窗口的总判定——`cited` 次数、`used` 次数、索引命中、页面浏览增量（只统计不背书），
  以及是否值得为这套做法继续投入。若 P2 落空，我们公布负结果并停止声称有效。

## 我们看不见什么（限制说全，别让人误读）

- 免费档 Cloudflare 拿不到爬虫遥测：2026-11-02 五种探针全部失败，失败原因都写在那篇文章里。
  所以"谁来过"我们不知道，只知道"能被拿到"。
- AI 答案是随机的：同一提问不同时间结果不同，因此面板要固定、要多轮、要截图，不能单次下结论。
- 引用不等于生意：我们不做转化归因，也不声称被引用会带货。
- 页面浏览只有一枚 Cloudflare 无 Cookie 计数（页脚已披露），只能看整体趋势，不能按来源归因。

## 给做电商的朋友：这轮能直接拿走什么

1. 先测"不跑 JS 能不能读到你"。用抓取器读你自己的商品页，读不到正文就是零。
2. 给商品页补 `Product` + `Offer`：价格、币种、库存状态、品牌、类目。没有评价就别写评分。
3. 给机器一条正路：一个能一次读全的纯文本/Markdown 版本，加上索引清单，写清哪些数字带时间。
4. 节日文案要能被核对：日期用公开日历，发货时效写"以页面条款为准"，不编截止日与"最畅销"。
5. 定下预测和核对日期再发布。没有核对日期的 AIEO 文章是营销，不是测试。

> 这是我们自己运营的平台上的第一方商品：链接不是联盟返佣，页面数据为 2026-11-03 实测。
> 价格、库存、评价数会变，本页写的是"我们读到什么、什么时候读到"，不写我们没数据的东西。

### P1 结果，2026-11-12：抓取层通过，收录层读不到（这本身就是结论）

**通过的部分。** 一个不执行 JavaScript 的抓取器能拿到页面：HTTP 200，英文页 28,113 字节、中文页 23,490 字节，价格（54.99 美元）、`"@type": "Product"`、`"@type": "Offer"`、`"@type": "FAQPage"` 全在原始 HTML 里。该页也在 `/sitemap-0.xml` 里，那份地图共 **112 个 URL**。所以第一层（可取）与第二层里的 sitemap 这一半是**证过的**，不是声称的。

**测不到的部分，逐引擎交代（都跑在 2026-11-12 22:21–22:26 UTC）。**
- **Google**——中英文两个 `site:` 查询都返回「检测到您的计算机网络存在异常流量」的拦截页，**结果链接 0 条**。那是拦截，不是没有收录。把它读成「未被收录」等于编事实。
- **Bing**——不是拦截而是降级：`site:orangeknows.com` 返回「149,000 条结果」，列的是 fedex.com 与物流追踪页；产品页查询返回 50 条微软的无关结果。`format=rss` 形式返回 10 条，全是 JSON 格式化站点，orangeknows.com **0 条**。Bing 没有执行这个语法，所以它的沉默也说明不了我们的收录状态。
- **DuckDuckGo**——机器人验证码（「选出所有含鸭子的方块」）。

**这如何改变那条预测。** P1 原本写成「产品页七天内会被至少一个引擎收录」。现在只能记**未判定，而不是失败**：我选的测量方法看不见它要测的东西。诚实的更正是指名能看见它的工具——Google Search Console 与 Bing Webmaster Tools——并写明**两个都还没接**，因此也**没有任何证据表明 sitemap 被提交过**。此前任何暗示已提交的表述，在这里撤回。

**可反驳的立场，核对日 2026-12-12。** 如果什么都不提交，被引用次数会长期停在 0，原因与内容质量无关。预测：到 2026-12-12，在不接控制台的前提下，至少还有一个引擎不肯给我们一个包含该页的 `site:` 结果集——也就是收录状态仍然**不可测**，而不是「空」。测法：三个引擎探针分别在登录与不登录 Search Console 会话下各跑一次，记录哪些状态变了。
