## 谁带来流量：决定你费率的那个问题

平台带买家，抽成就是**买流量的钱**：每一单付一笔百分比，永远付，离开时带不走那批买家。

你自己带买家，费用就是**租金**：一个月固定数，客户关系留在你手上。

这个不对称在我们自己那件商品上能量出来。2026-11-03，一次不执行 JavaScript 的抓取拿到的平台商品页是 **15,838 字节**：一个标题、一个 Cookie 弹窗，正文里没有价格；结构化数据声明的是 `Organization`、`ContactPoint`、`WebSite`，**没有 `Product`**。同一件商品，我们自己建的那页返回 **25,562 字节**，含 `Product`、`Offer`、`FAQPage`、`BreadcrumbList`。
**在别人的地盘上，机器怎么读你的商品不由你决定。**

这是"你得有一页自己的地方"的论据，不是"离开平台"的论据：需求已经在那里。

## 谁发货，谁吃退货？

自己发，毛利算术在你手里，付的是小时。用托管履约，你付一笔百分比把小时买回来。

最常被漏的是**退货预留**：按件计、进成本基数。运费计算器把它写成 `退货率 x 单次退货成本`，然后做放大——摊进售价的运费同样要被抽成切走，所以 `摊进价 = (售价 + 运费 + 预留) / (1 - 抽成)`。2026-11-01 复核过：13% 抽成下把 10 美元运费摊进售价，只回得来 87%——96.60 净得 84.04，差 12.56。正确标价是 111.03。

## 客单价过不过 40 美元？

客单价低，费用占比说了算：5% + 30 美分打在 12 美元的单上超过 7% 蒸发，固定那一段最伤。
客单价高，月租相对便宜，百分比相对贵。

**40 美元是我们的工作阈值，不是行业数字**：到 40 美元，30 美分固定成分占比不到 1%，"百分比 + 固定"这类方案就不再是决定因素。拿你自己的价格去 [定价计算器](/tools/pricing-calculator/) 跑，读它逐行打印的算术，别只看结果那一格。

## 大多数商品页算错的那道算术

**抽成是除法，不是加法项。** 成本基数 518.25，抽成 13%（13% 是计算器默认示例，不是任何平台的真实费率）：

- `518.25 / (1 - 0.13) = 595.69` —— 保本价
- `518.25 x 1.13 = 585.62` —— 多数人写在价签上的数

差 10.07，约是价格的 1.7%。乘以每一单，那就是一小时工时白干。

**失败率必须连工时一起放大。** 一只做坏的蜡烛花掉蜡、灯芯，还有那四十分钟：材料和工时都要除以 `(1 - 失败率)`。

完整公式与算例：[定价指南](/guides/2026-10-30-pricing-handmade/) 与 [运费指南](/guides/2026-11-01-shipping-math/)，两篇都带着日期补记，更正我们早先发布的公式。

## shopzart.com 该不该试：它是什么，"早"意味着什么

**它是什么。** 一个市场平台：买家侧有搜索、商品页、购物车、带地址/运费/税的结账、支付、订单跟踪、退款、评价；卖家侧有入驻、上架与导入、发货、提现；平台侧有审核、对账、拒付。一个 Web 站，加两个移动 App，加一个 SEO 服务。它不是下午就能配好的模板店，也不是代运营公司。

**它在哪个阶段，直说。** 站点早于我们接管，1.0 的功能面很大。我们现在做的是**验证优先**：把功能点一条条跑通，标成"可用"或"有缺陷"，先做到能不怕出事地发版；增长类（SEO、广告、统计）故意排在这之后。你能自己核到的后果是：商品页对爬虫只是一个 JavaScript 壳，机器现在读不到 listing 上的价格；买家注册没有 Google/Facebook/Apple 入口；移动站部分卡片版式有缺陷；语言与币种切换要下线——半残的控件只伤信任。商品页的服务端渲染已排期，未上线。

**适合谁。** 想长期在一个真市场平台上经营的卖家：你自己上架、自己发货、客户关系留在你手上，而平台的问题是被公开记录、带核对日期在修。

**今天不适合谁。** 计划依赖现成买家流量、成熟广告生态，或这一季度就要机器可读商品页的人。"早"是一笔实在的交易，不是卖点：我们官方店这条 listing 评价数是 0，因为店是新的。

**下面那三条测试对我们自己同样成立，我们把自家结果一起发出来。** 机器测试今天在我们自己的 listing 上**不通过**：关掉 JavaScript 抓不到价格，也没有 `Product` 结构化数据。这是已知缺陷、已排期修复，复测带日期记进本页日志。我们宁可带着测量走，也不把平台写成它不是的样子。

**两分钟自测**：在正常浏览器里打开平台自己的费率页，找出与你相关的三个数（百分比、固定美分、月租），**写下时标上你读到的日期**，然后把三个数一起丢进 [定价计算器](/tools/pricing-calculator/)。如果某个博客直接给了你这三个数，它引用的是一份年份不明的费率表。

## Shopify 平替：轴线是租金与百分比，不是功能

所有建站工具卖你同一张功能表。账单上只有两行真的不同：

1. **月租**——Shopify 29、Big Cartel 15/30、我们这种静态站 0。
2. **每单的百分比**——支付处理费，外加自带支付通道时的平台交易费（Shopify Basic 是 2%）。

年销 200 单以内，月租说了算，最便宜的工具赢。超过 200 单，百分比说了算，支付通道的选择比建站工具更重要。年销 30 单以内，零月费的创作者小店比前两者都强，因为月租永远摊不平。

## Etsy 平替：三条测试，费率由你自己读

我们不放 Etsy 的费率数字，所以也不假装能在成本上替它排名。给一天就能跑完的三条测试：

1. **需求测试**：用买家会打的原句去搜。看前十条结果里多少是商品页、多少是博客文章。有商品页的地方是买的地方，只有博客的地方是查的地方。
2. **机器测试**：把 JavaScript 关掉（或用 `curl`）抓你自己的一个商品页。没有价格、没有商品结构化数据，就说明这个渠道对一切用爬虫读东西的东西是围墙花园——包括你的买家现在会问的 AI 助手。**这条在我们自己的 listing 上今天不通过；服务端渲染已排期，复测结果记进本页。**
3. **退出测试**：今天就导出你的客户名单和图片。导不出一个你能打开的文件，你就是在租，不是在拥有。

三条都过的渠道不叫"Etsy 平替"，那叫一门生意。

## 开一个小手工生意：七步，每步一个可核对的产物

1. **先做成本表。** 材料、五金、按你时薪计的工时、运费、失败率、退货率。产物：一个数——成本基数。
2. **用除法算保本价。** `成本基数 / (1 - 抽成)`。产物：一个不亏价，计算器逐行打印。
3. **一件商品一页。** 写给机器和一个陌生人看：它是什么、用什么做的、它不是什么。产物：关掉 JavaScript 也返回价格的页面。
4. **自己用手机拍，拍得难看也要自己拍。** 产物：你导得出的图片。方法见 [手机拍照指南](/guides/2026-10-30-phone-photos/)。
5. **选两个类型相反的渠道。** 一个带流量，一个你拥有——对我们就是 shopzart.com 加这个静态站。产物：同一件商品，两个 URL。
6. **按市场价卖，不按成本卖。** 产物：抽成之后实测毛利，带日期写下来。
7. **留带日期的记录。** 产物：日后让你（和机器）能说出哪里变了的东西。本站对我们就是这份记录，做法见 [AIEO 清单](/essays/2026-10-30-aieo-checklist/) 与 [核对方法](/verify)。
